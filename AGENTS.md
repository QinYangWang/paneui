# qinyang/ui — agent guide

A shadcn registry (`@qinyang/*`, style `base-nova`, headless primitives from `@base-ui/react`,
Tailwind v4, motion/react) plus its Next.js docs site. These rules keep every coding agent on one
style. **The design rules live in one place: the `qinyang-design` skill (`skills/qinyang-design/SKILL.md`
and its `references/`).** Read it before any UI work; this file only adds what is specific to this repo.
`pnpm lint` (`@shadcn/lint` + `qinyang/concentric-radius`, in `eslint.config.mjs`) and `pnpm design:check`
(the skill's `scripts/check.mjs`, configured by `qinyang-design.config.json`) enforce most rules.

**After making changes, run `pnpm lint`, `pnpm exec tsc --noEmit -p .` and `pnpm design:check` and fix all errors.**
After changing radii or padding on nested surfaces, also run `pnpm audit:radius` against a fresh static export.

## Repo layout

A pnpm workspace. The docs site and the registry stay at the root (registry paths, `components.json`
aliases and the Pages workflow all assume it); publishable packages live in `packages/`.

- `/` — Next.js docs site (`app/`, `components/docs/`, `content/`, `lib/`) and the registry (`registry.json`,
  `registry/base-nova/`, built to `public/r/`). `pnpm install` at the root installs the site and `packages/*`.
- `packages/cli/` — the `qinyang` CLI (npm name and bin in its `package.json`; the docs read the name from there).
  `pnpm cli:build`, `pnpm cli:test` (node:test against a mock registry). Released by pushing a `cli-v<version>` tag
  (`.github/workflows/release-cli.yml`, needs the `NPM_TOKEN` secret). Excluded from the root `tsc`; it has its own tsconfig.
- `apps/desktop/` — the Electron shell. **Not** a workspace member: its own `pnpm-workspace.yaml` and lockfile, so root
  installs and CI never fetch Electron or build node-pty. Install it with `pnpm install` inside `apps/desktop/`.
- `skills/` — our skills (design, copy density, puffy icons). `.agents/skills/` holds the vendored third-party skills
  (`skills-lock.json`); `.claude/skills/` only symlinks to them.
- `CLAUDE.md` imports this file; edit this one.

Import library code as `@/registry/base-nova/ui/<file>` or `@/registry/base-nova/blocks/<name>/<file>`.
**Library** files own their appearance (no `no-restyle`; arbitrary values only warn).
**Consumer** files compose the library: tokens only, `className` on a component for
layout, plus the per-family contracts (Card parts take spacing, titles take
typography, Buttons take margins and `w-full`). If lint says a component "owns" a
style, use a variant/size or style a plain wrapper `<div>`; add a variant to the
component only if the design really needs a new treatment.


## Design rules: the `qinyang-design` skill

Single source for colour, accent, elevation, radius and concentric nesting, type, density, spacing,
layout, components, icons and brand marks, charts, motion, focus, dark mode, copy density and wording.
`SKILL.md` has the numbered rules; the exact values are in `references/` (foundations, components,
layout, copy, icons, charts, motion-a11y, registry). `/docs/skill` renders the same rules with live
Recommended / Avoid examples (`components/docs/skill-examples.tsx`, keyed by rule title); add an example
there when you add a rule. Change a rule in the skill first, then the code.

Repo-only details the skill doesn't carry:

- **Theme generation**: accent presets, chart hues and the token section of `app/globals.css` come from the
  maintainers' generator (`/workspace/work/round16/gen/build_globals.py`, then `python3
  /workspace/work/regen-theme.py`, which also writes `theme-accents.css`,
  `components/docs/accent-presets.generated.ts`, the accent picker CSS and the `theme*` / `fonts` items).
  Never hand-edit generated files. New tokens: add them to `app/globals.css` with a `.dark` value and an
  `@theme inline` mapping in a separate reviewed change, then regenerate.
- **Icon styles**: `components/icons.tsx` is the only hand-drawn icon file. Never edit
  `registry/base-nova/icons/outline/icons.tsx`; change the source or `scripts/icon-outline-overrides.mjs`
  and run `pnpm icons:gen` (also the first step of `pnpm registry:build`).
- **Text sizes and tailwind-merge**: `lib/utils.ts` (`@qinyang/utils`) teaches tailwind-merge the `text-ui*`
  sizes; it does not know the `frame-*` utilities.
- **Notes**: `notes/foundation-v2.md` (why the values are what they are), `notes/radius-audit.md` (audit
  triage), `notes/docs-shell.md` (docs chrome), `notes/icon-usage.md`, `notes/native-style.md`.
- **Review skills**: the `better-*` skills in `.agents/skills/` (`better-interface` for a full review,
  `interface-review` for a diff, `better-ui`, `better-typography`, `better-layout`, `better-colors`,
  `better-accessibility`, `better-writing`). Where they and the design skill differ, the design skill wins.

## Adding a registry item

1. Component: `registry/base-nova/ui/<name>.tsx` (or `blocks/<name>/…`). Export named
   parts, `data-slot` on each, variants with `cva`, forward `className` through `cn`.
2. Example: `registry/base-nova/examples/<name>-demo.tsx` (default export), written as
   a consumer: it must pass consumer lint.
3. `registry.json`: add the item (`name`, `type`, `title`, `description`,
   `dependencies`, `registryDependencies` such as `@qinyang/theme` / `@qinyang/icons` /
   `@qinyang/icon-chip`, `files`, and `meta.category`, one of `Foundations, Forms,
   Overlays, Display, Navigation, Text, Motion, Data, Agents, Charts, Blocks`
   (see `ORDER` in `lib/docs.ts`)).
4. `components/docs/demos.tsx`: import the demo and add `"<name>": <Name>Demo`.
5. `pnpm lint`, `pnpm exec tsc --noEmit -p .`, `pnpm design:check`, then `pnpm registry:build` to regenerate `public/r/`.

## Lint exceptions

Fix the code first. If a rule is wrong for a legitimate case, use one
`// eslint-disable-next-line shadcn/<rule> -- <reason>` (JSX: `{/* … */}`) on that
line only, with a reason. List them with `rg "eslint-disable.*shadcn/"`; each is a design decision to review.

## Component docs pages
Every registry:ui item has `content/docs/<name>.ts` (type `ComponentDoc` in lib/doc-types.ts: usage, composition, examples, notes, api) and examples in `registry/base-nova/examples/<name>/<id>.tsx`. After adding or renaming one run `pnpm docs:gen` (regenerates content/docs/index.generated.ts and components/docs/examples.generated.tsx; commit both). API tables list only props the library adds or changes; the rest is `extends` with a link to the primitive's docs. Examples render client-only. Each docs page gets a Markdown copy (`out/docs/<name>.md`) from `pnpm docs:md` (`scripts/gen-docs-md.mjs`) after `next build`. Guide pages are converted from their HTML, steered by markup hooks: `data-md-skip` (or `data-md="skip"`) leaves page chrome, interactive previews and phone-only duplicates out; `data-md-text="…"` writes a short fallback instead of a widget; `data-md-only` (with `hidden`) is written only to the Markdown; `data-md-after=":"` separates a label from its description; `data-md="links"` turns link tiles into `- [title](url): description` (title from `data-md-title`, description from `data-md-desc`). After `docs:md`, run `node scripts/audit-docs-md.mjs` (glued words and numbers, empty links, repeated lines, UI chrome, fragments, empty table columns); it must report 0.

The docs site is built from the library: shell header tabs (`NavigationMenuLink variant="tab"`), sidebar (`SidebarNav`), outline (`Outline` / `OutlinePopover`), page header (`PageHeader size="lg"`), pager and tiles (`Card interactive render`), tables (`SimpleTable`). Use library components in `app/` and `components/docs/` too; add a variant or an item when one is missing.


## Wording: no third-party names or provenance

Rule 30 of the design skill (`references/copy.md` › Wording). Code comments, UI copy, demo data and docs
prose never name the projects, products or libraries this library was modelled on or is built with, and
never use provenance phrasing. Allowed because they are needed to work: imports and package specifiers,
`package.json` / `registry.json` dependencies and the chips generated from them, identifiers and public API
names, the shadcn CLI commands, the Agent Client Protocol and the agent presets it launches, and the stack
users must have (React, Next.js, Tailwind CSS 4). Licence attribution lives only in `THIRD_PARTY_NOTICES.md`
(keep it and `LICENSE`; add a notice there when you adopt values or code from another project).
`pnpm design:check` (`forbidden-names`) scans comments, JSX text, prose strings, markdown and registry
descriptions against the hashed list in `qinyang-design.config.json`; add a name with
`node skills/qinyang-design/scripts/check.mjs --hash "name"`.
