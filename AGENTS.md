# qinyang/ui — agent guide

A shadcn registry (`@qinyang/*`, style `base-nova`, headless primitives from `@base-ui/react`,
Tailwind v4, motion/react) plus its Next.js docs site. These rules keep every coding agent on one
style. `pnpm lint` enforces most of them (`@shadcn/lint`, rules in the
"qinyang/ui design-system rules" block of `eslint.config.mjs`); the rest is on you.

**After making changes, run `pnpm lint` and `pnpm exec tsc --noEmit -p .` and fix all errors.**
After changing radii or padding on nested surfaces, also run `pnpm audit:radius` against a fresh static export.

Import library code as `@/registry/base-nova/ui/<file>` or `@/registry/base-nova/blocks/<name>/<file>`.
**Library** files own their appearance (no `no-restyle`; arbitrary values only warn).
**Consumer** files compose the library: tokens only, `className` on a component for
layout, plus the per-family contracts (Card parts take spacing, titles take
typography, Buttons take margins and `w-full`). If lint says a component "owns" a
style, use a variant/size or style a plain wrapper `<div>`; add a variant to the
component only if the design really needs a new treatment.

## Tokens (`app/globals.css`)

- **Colors**: `background`, `foreground`, `card`, `popover`, `surface-sunken`, `surface-standout` (+ `standout-foreground`),
  `primary` (+ `-hover`, `-active`, `-foreground`, `-subtle`, `-subtle-hover`, `-border`), `secondary`, `muted`,
  `muted-foreground`, `fg-tertiary`, `fg-disabled`, `accent`, `destructive` / `success` / `warning` (each + `-hover`,
  `-foreground`, `-subtle`, `-border`), `border`, `border-subtle`, `border-strong`, `input`, `ring`, `code`,
  `chart-1`…`chart-8`, `shell`, `shell-border` (each `*-foreground` where defined). Washes use the `-subtle` tokens
  (`bg-success-subtle`, `inset-ring inset-ring-success-border`); opacity modifiers (`ring-primary/20`) stay fine for
  one-offs. Never palette colors (`bg-zinc-100`), hex, or `[#…]` in components. `white`/`black` only for scrims
  (`bg-black/40`); text on a solid uses its `*-foreground`.
- **Visual direction: native desktop on the foundation set (since 2026-10-16)**. The 13px scale, densities and
  shell layout from 2026-10-14 stay; fonts, colours, radius and shadows were replaced. Summary in
  `notes/foundation-v2.md` (licence notices in `THIRD_PARTY_NOTICES.md`).
- **Colours (since 2026-10-16)**: values are steps of 12-step colour scales (hex, with display-p3 under
  `@supports (color: color(display-p3 1 1 1))`), written straight into the tokens; roles in comments in
  `app/globals.css`. Light: page, card, popover `#fff`, shell `#f6f6f6`. Dark: page `oklch(15% 0 0)`, card `#111`,
  popover `#222`, shell `#000`. Text is translucent gray: foreground a12, `muted-foreground` a11, `fg-tertiary` a9,
  `fg-disabled` a8. `secondary` and `muted` are gray a3, `accent` gray a4: **translucent fills**, not surfaces; use
  them for hover/selected/track fills, and `bg-card` / `bg-popover` / `bg-background` for anything opaque.
  `border` gray a3, `border-subtle` a2, `border-strong` and `input` a6. States: `destructive` = tomato 9,
  `success` = green 9, `warning` = orange 9, each `-hover` 10, `-subtle` a3, `-border` a6. Charts `chart-1`…`chart-8`
  unchanged (teal, lime, pink, sky, purple, blue, emerald, yellow). No gradient sheens, inset highlights, text-shadows or
  glows. App chrome: `bg-shell` and the `shell-inset` utility (0.5px `shell-border` hairline, `rounded-shell`, 3px gap).
- **Accent = eight roles (since 2026-10-16)**: `primary` (solid, step 9), `primary-hover` (10), `primary-active` (11),
  `primary-foreground` (white), `primary-subtle` (a3), `primary-subtle-hover` (a4), `primary-border` (a6), `ring`
  (a8 light / a9 dark, used at `/50`). Default blue `#0090ff`. Presets (neutral, green, orange, rose, violet) are
  `html[data-accent="…"]` + `.dark` blocks that swap the eight on the same steps of their own scale (neutral = the
  inverted black/white solid); each ships as `theme-<name>`. Edit them in `/workspace/work/round16/gen/build_globals.py`
  or `app/globals.css`, then run `python3 /workspace/work/regen-theme.py`. Filled buttons hover to `bg-primary-hover`,
  not `/90`. Never pair `bg-primary` with `text-white`: use `text-primary-foreground` (neutral's dark primary is
  near-white). Charts never use `primary`.
- **Elevation**: four levels, `--shadow-border` / `--shadow-default` / `--shadow-lg` / `--shadow-xl` (light and
  dark), behind Tailwind's `shadow-xs` / `shadow-sm` / `shadow-md` + `shadow-lg` / `shadow-xl`. Components use the
  named tokens on top: `shadow-raised` (= default; resting controls, cards, tables, code blocks) →
  `hover:shadow-raised-hover` (ring a step darker); `shadow-surface` (= lg; popovers, menus, floating panels);
  `shadow-xl` for dialogs, alert dialogs, drawers, sheets and the command palette; `shadow-well` (inset `input`
  hairline for fields and tracks); `shadow-chip` (= border; kbd, small chips); `shadow-primary` (filled primary).
  Dark elevation is an inset white hairline plus deeper drops on the floating levels. Hover on rows, menu items,
  ghost/outline buttons and nav is a fill (`bg-secondary`), not a ring.
- **Focus**: `focus-visible:ring-2 focus-visible:ring-ring/50`.
- **Radius (since 2026-10-16)**: base `--radius` 0.5rem with multiplier steps → `rounded-xs/sm/md/lg/xl/2xl/3xl/4xl/5xl`
  = 2/4/6/8/10/12/16/20/24px (`rounded-2xs` is an alias of xs; `rounded-shell` 12px for the rail inset panel).
  Presets: none 0, sm 0.375rem, default 0.5rem, lg 0.625rem (the old default), xl 0.875rem. **Every radius derives from
  `--radius`** (since 2026-10-16): never hardcode px/rem radii in library files; use a token or
  `rounded-[calc(var(--radius)*k)]` so presets rescale it (`html[data-radius="none|sm|lg|xl"]`, a custom
  value inline on <html>, `theme-radius-*` registry items). Only 1–2px caret/bar radii, `rounded-full`
  and `rounded-[inherit]` stay literal. Motion-animated `borderRadius` numbers (feedback-widget,
  morphing-search, aspect-ratio) and SVG `rx` in charts are literal by design.
  Buttons, inputs, select/combobox triggers, tab lists, menu/select rows: `rounded-lg` (8px); xs
  buttons and checkboxes `rounded-sm`; tab indicators inside a `p-0.5` list `rounded-md`;
  menus, context menus, select and combobox popups `rounded-2xl` (`p-1`, concentric with `rounded-lg` rows:
  12 − 4 = 8px); cards, tables, code blocks `rounded-xl`; two-layer inset cards (`p-1`) `rounded-2xl`; containers
  that hold controls 8px in (`p-2` prompt bars, composers, sidebars, rails) `rounded-3xl`; dialogs `rounded-3xl` (16px). Two-layer cards: `<Card variant="inset">` + `<CardPanel>` (tinted frame, p-1, raised panel) for presented content (demos, media, code, featured plans) only; dense dashboard cards stay default.
  Keep radii concentric (outer = inner + padding): see **Nested radii** below. `rounded-full` only for inherently
  round things: avatars, dots, switches and slider thumbs, badges/tags, icon-only
  circular buttons, progress bars.
- **Nested radii (hard rule, since 2026-10-14)**: any rounded element placed inside a rounded
  container with padding uses `rounded-inner` (or an explicitly computed concentric token), never
  the same token as its container. Declare the container with the `frame-*` utilities from
  `app/globals.css` and the child follows it:

  ```tsx
  <div className="frame-2xl frame-p-2 bg-card">        {/* 18px, padding 8px */}
    <li className="rounded-inner hover:bg-secondary">… {/* 18 − 8 = 10px */}
  ```

  | Utility | On | Does |
  | --- | --- | --- |
  | `frame-{sm…3xl,shell}` | container | sets its radius and publishes radius − inset to descendants |
  | `frame-p-{n}` | container | padding on all sides **and** the inset used in the maths (`pr-1.5` etc. still override one side) |
  | `frame-inset-{n}` | container | only the inset, when the gap comes from a wrapper's `px-2 pb-2`, a gap, or asymmetric padding |
  | `frame-border` | container | adds the container's 1px border to the inset |
  | `rounded-inner`, `rounded-{t,b,s,e}-inner` | child | radius = frame radius − inset (min 2px, 0 when the frame is square); outside any frame it falls back to `rounded-lg` |
  | `frame-inner` | child that is itself padded | takes `rounded-inner` and publishes its own inner radius (combine with `frame-p-*`/`frame-inset-*`) |
  | `rounded-inner-{token}` | child whose own radius is not `rounded-lg` | concentric inside a frame, `{token}` outside one (`rounded-inner-md` for a 6px row) |
  | `rounded-inner-or-{token}` | child whose inset can be too large (a key cap or a mark 8px into a button) | the frame's inner radius where it is usable, else `{token}` capped at `rounded-sm` |

  Two levels (`frame-*` → `frame-inner` → `rounded-inner`) are supported; a third must compute its
  value. A component that uses `rounded-inner` puts its `frame-*` on its own root, so it never
  follows a frame it does not own. A consumer `rounded-*`/`p-*` on the same element still wins
  (utility order), but then the published inset is stale: change the `frame-*` instead.
  When the rule applies: inset ≤ 8px is always concentric. If radius − inset would be < 4px the
  container is too loose for concentric: the child keeps its own token (or shrink the padding /
  grow the container, as `attachment-upload` does). For insets of 9–15px, surfaces (rows, panels,
  wells, media, thumbnails) stay concentric; self-contained controls (buttons, icon chips, inputs)
  keep their token. Never put a child's radius above its container's.
  Checks: `pnpm lint` warns (`qinyang/concentric-radius`) when a direct JSX child's literal radius
  token breaks the rule; `pnpm audit:radius` (needs the static export served, `BASE_URL`, default
  `http://localhost:3123`) measures every docs page in the browser, including opened menus and
  hovered rows from `scripts/audit-radius.config.mjs`, and writes a report grouped by page and
  component (allow-list intentional cases there, each with a reason). Triage notes:
  `notes/radius-audit.md`.
- **New tokens**: add them to `app/globals.css` (a scale step in hex, or `oklch()`), with a `.dark` value
  and an `@theme inline` mapping, in a separate reviewed change, then run `regen-theme.py`.

## Typography

Inter (`font-sans`: "Inter Variable" → Noto Sans SC for CJK → system stack, `font-feature-settings: "ss03"`) with
`letter-spacing: normal`; JetBrains Mono → system mono (`font-mono`, features off) for code, keys and terminals;
Newsreader → Noto Serif SC (`font-serif`) for the `typeset-reading` preset. Fonts are self-hosted from
`@fontsource-variable/*` through `app/fonts.css` (registry item `fonts`, hidden); the theme falls back to
system fonts without it. Weights: `font-normal` 400, `font-semimedium` 450, `font-medium` 500, `font-semibold` 600,
`font-bold` 700. **Desktop 13px scale** (unchanged with the new font):
`text-ui-2xs` 10 · `text-ui-xs` 11 (meta, shortcuts, counts) · `text-ui-sm` 12 (captions,
badges, small controls, tooltips) · `text-ui` 13 (default UI: buttons, inputs, menus, nav,
body inside components) · `text-ui-lg` 14 (lg controls, card titles). Library components use
the `text-ui*` sizes; Tailwind's `text-sm`–`text-2xl` stay for reading copy and page/section
headings in consumers, `text-3xl`+ for hero only. Titles `font-semibold` (`tracking-tight`
only from `text-xl` up); labels and buttons `font-medium`. Secondary text is
`text-muted-foreground`. `lib/utils.ts` extends tailwind-merge so `text-ui*` merge as font
sizes (shipped as `@qinyang/utils`, a dependency of `@qinyang/theme`). Never `text-[10px]`/`text-[11px]`.

## Density

Desktop density: buttons `h-8` default, `sm` h-7, `xs`/`icon-xs` h-6, `lg` h-9, `icon` 32,
`icon-sm` 28; inputs, select/combobox triggers `h-8` (`sm` h-7), `px-2.5`; menu/select/combobox
rows `min-h-6.5` (26px) `px-2` `rounded-lg`, popup padding `p-1`, separators `mx-2 my-1`; tooltips
`px-2 py-1 text-ui-sm`; sidebar rows `h-8` (sub rows `h-7`) with `text-ui`, icons
`text-muted-foreground`, hover `bg-secondary`, active `bg-foreground/6`; checkbox/radio 16px,
switch 32×20. Disabled is `opacity-64`.

## Spacing rhythm

4px grid (Tailwind spacing). Inline gaps `gap-1.5`–`gap-2` (icon + label), control
groups `gap-2`–`gap-3`, card padding `p-4`–`p-6`, stacked sections `gap-6`–`gap-10`.
Card inner parts own their padding; put space between things with `gap` on the parent
or margin on the child, not padding on a component.

## Icons (summary of `notes/icon-usage.md` + puffy rules)

- All icons come from `@/components/icons` (`@qinyang/icons`), never another icon package or ad-hoc SVG.
- Outline style: never edit `registry/base-nova/icons/outline/icons.tsx`; change `components/icons.tsx`
  or the override map, run `pnpm icons:gen`, and check new icons in both styles (`notes/icon-usage.md` › Outline variant).
- Drawing: 18×18 grid, ~2.5px padding, only the `puff` (filled, 1.5 round stroke)
  and `line` (1.6 stroke, round caps) primitives, `currentColor` only, `path`/`circle`/`rect` only.
- Two families never mixed in one group: **solid (puff)** and **line/ring**. Nav,
  rails, docks, tab bars and palettes use solid (`InboxIcon` not `MailIcon`,
  `CalendarDaysIcon` not `CalendarIcon`, `TerminalSquareIcon` not `TerminalIcon`).
  Line glyphs are for controls (chevrons, close, add, search).
- Nav/sidebar/palette icons: 16px, `text-muted-foreground`, active `text-foreground`, bare.
  The docs site sidebar (`components/docs/docs-nav.tsx`) is text-only: no per-item icons (see `notes/docs-shell.md`).
  Inline icons: the button sets the size.
- Title/header/card/alert icons go in `<IconChip>` (sizes sm 24 / default 32 / lg 40 / xl 48;
  tones neutral, primary, success, warning, destructive, solid); one size per list.
  Add `@qinyang/icon-chip` to `registryDependencies` when used.
- On an icon, `className` takes size, layout, a token text color, opacity and motion only.

## Motion

- motion/react springs, bounce-free and critically damped-ish: the house range is
  `{ type: "spring", stiffness: 380–520, damping: 26–42, mass: 0.5–0.7 }`
  (e.g. `420/38/0.6` for settles, `500/30` for snappy toggles). Icon cross-fades:
  `{ type: "spring", duration: 0.3, bounce: 0 }`.
- CSS: `duration-150` (press, hover, high-frequency), `duration-200` (state changes),
  `duration-300` (reveals, panels); easing `ease-[cubic-bezier(0.22,1,0.36,1)]`
  (or `EASE = [0.22, 1, 0.36, 1]` in motion); the overshoot curve
  `cubic-bezier(0.34,1.56,0.64,1)` only for playful pops.
- Transition named properties (`transition-[box-shadow,background-color,color]`,
  `transition-colors`, `transition-transform`), never `transition-all`.
- Every movement, scale or blur is gated: `useReducedMotion()` / `motion-reduce:` /
  `motion-safe:`, falling back to an opacity cross-fade.
- **No press scale on standard controls** (Button, triggers, toggles, nav rows, checkbox, radio):
  native controls answer with a fill change. Press scale is kept only where the
  motion is the component's point (expanding-arrow-button, expandable-control, card-folder,
  message-bubble, hold/slide action buttons). Popups enter from `scale-98` + opacity.

## Light and dark

Every change must look right in both themes (`.dark` on `<html>`). Use tokens, not
`dark:` overrides with palette colors; check the gallery in both themes
(theme toggle in the docs header).

## House rules from the better-* skills

Jakub Krehel's skills are installed in `.agents/skills/`. Load the relevant one for UI work:

| Work | Skill |
| --- | --- |
| Full review of a component, block or page | `better-interface` (runs all the better-* skills) |
| Reviewing a diff / branch / PR | `interface-review` |
| Surfaces, radii, shadows, icons, motion | `better-ui` |
| Type scale, wrapping, numerals, punctuation | `better-typography` |
| Grouping, alignment, responsive structure | `better-layout` |
| Color tokens, palettes, contrast | `better-colors` |
| Focus, keyboard, ARIA, forms, reduced motion | `better-accessibility` |
| Labels, errors, empty states, confirmations | `better-writing` |

Where our tokens and components above don't already decide, adopt their exact values as
house rules:

- **Press**: no press scale on standard controls (see Motion); motion-showcase pressables
  may scale to `0.96` over `150ms` `ease-out`, disabled never scales.
- **Concentric radii**: outer radius = inner radius + padding (+ border) on nested
  surfaces; use `frame-*` + `rounded-inner` (see Tokens › Nested radii for when it applies).
- **Text wrapping**: `text-balance` on headings and titles, `text-pretty` on body
  paragraphs and descriptions.
- **Numbers**: `tabular-nums` on any number that updates, aligns in columns, or
  counts (prices, timers, tickers, tables).
- **Reduced motion**: movement/scale/blur only under `prefers-reduced-motion: no-preference`;
  under reduce, cross-fade opacity instead of removing motion abruptly.
- **Transitions**: name the properties; never `all`. `will-change` only for a seen
  stutter, naming the property.
- **Enter/exit**: staggered entrances 100ms apart (opacity + 4px blur + 12px
  translateY, 300ms ease-out); exits shorter (150ms, -12px). `initial={false}` on
  `AnimatePresence` state swaps.
- **Overlays**: `overscroll-contain` on scrollable dialogs, drawers, menus.
- **New colors**: `oklch()` tokens in `app/globals.css`, light and dark.

## Adding a registry item

1. Component: `registry/base-nova/ui/<name>.tsx` (or `blocks/<name>/…`). Export named
   parts, `data-slot` on each, variants with `cva`, forward `className` through `cn`.
2. Example: `registry/base-nova/examples/<name>-demo.tsx` (default export), written as
   a consumer: it must pass consumer lint.
3. `registry.json`: add the item (`name`, `type`, `title`, `description`,
   `dependencies`, `registryDependencies` such as `@qinyang/theme` / `@qinyang/icons` /
   `@qinyang/icon-chip`, `files`, and `meta.category`, one of `Foundations, Forms,
   Overlays, Display, Navigation, Text, Motion, Data, Agents, Charts, Blocks`
   (see `ORDER` in `lib/docs.ts`)).
4. `components/docs/demos.tsx`: import the demo and add `"<name>": <Name>Demo`.
5. `pnpm lint`, `pnpm exec tsc --noEmit -p .`, then `pnpm shadcn build` to regenerate `public/r/`.

## Lint exceptions

Fix the code first. If a rule is wrong for a legitimate case, use one
`// eslint-disable-next-line shadcn/<rule> -- <reason>` (JSX: `{/* … */}`) on that
line only, with a reason. List them with `rg "eslint-disable.*shadcn/"`; each is a design decision to review.

## Component docs pages
Every registry:ui item has `content/docs/<name>.ts` (type `ComponentDoc` in lib/doc-types.ts: usage, composition, examples, notes, api) and examples in `registry/base-nova/examples/<name>/<id>.tsx`. After adding or renaming one run `pnpm docs:gen` (regenerates content/docs/index.generated.ts and components/docs/examples.generated.tsx; commit both). API tables list only props the library adds or changes; the rest is `extends` with a link to the primitive's docs. Examples render client-only.

## Copy density (hard rule; full skill in `skills/copy-density/SKILL.md`)

1. Component cards (gallery, any overview grid) show the name and the preview only. Never write the colon-list pattern ("X: a, b, c and d").
2. Where a live preview is shown, the text never restates what the preview shows. The preview is the explanation.
3. Implementation details (install paths, pixel values, variant lists, file locations) appear only in the detail page body, never in cards, nav, search or ledes.
4. Each example block on a detail page is title, preview and code. Use at most one lead-in sentence, and it must answer "when to use", never "what it is".
5. No adjective stacking (complete, comprehensive, powerful, seamless, robust, modern, flexible).
6. Self-check: any card or lede over two lines gets cut to one line.

A registry `description` is the page lede, the nav search text and `<meta>`, so it's one plain sentence of 12 words or fewer, with no values or lists. Long-form prose (guides, changelog, notes, blog and docs templates) renders inside `typeset typeset-docs` (`app/typeset.css`). Don't hand-style elements inside it, and put `not-typeset` on components dropped into it.

## Wording: no third-party names or provenance

Code comments, UI copy, demo data and docs prose (`content/docs/*.ts`, `app/**`, `components/docs/**`,
changelog, README, examples, registry descriptions) never name the projects, products or libraries
this library was modelled on or is built with, and never say "after X", "X-style", "X-like", "port
of", "inspired by", "based on". Describe what the thing does instead ("block editor", "desktop
density", "the dialog primitive", "the diff renderer", "the syntax highlighter").

Allowed, because they are needed to work: import statements and package specifiers, `package.json`
and `registry.json` `dependencies`, the dependency chips the docs generate from them, identifiers and
public API names (`notion-editor`, `NotionEditor`, the `shadcn/*` lint rule names), the shadcn CLI
commands users run, the Agent Client Protocol (the standard the agent workspace implements) and the
agent presets it launches (Claude Code, Codex, Gemini CLI), and the stack users must have (React,
Next.js, Tailwind CSS 4). Licence attribution lives only in `THIRD_PARTY_NOTICES.md` (keep it and
`LICENSE`; add a notice there when you adopt values or code from another project). Before
committing, `rg -i "synara|boardui|maily|notion-style|tiptap|base ui|dicebear|notionists|zoish|react email|remark|pierre|shiki|after "`
over the changed prose should find nothing new.
